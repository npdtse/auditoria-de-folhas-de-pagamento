1. Organização dos Arquivos

A aplicação é estruturada no modelo de aplicação de página única (Single Page Application — SPA) estática, composto por cinco arquivos principais sem dependência de etapa de compilação (build).

Arquivo Tipo Função Técnica
index.html HTML5 Interface principal da SPA. Contém as visões de carregamento de arquivo, painel de desvios auditados, manual de critérios e inclusão das CDNs.
style.css CSS3 Design system da aplicação. Define tokens de cores, modo claro/escuro, leiautes em Grid/Flexbox e responsividade para dispositivos móveis.
script.js JavaScript (ES6+) Motor da aplicação. Executa a leitura de arquivos, normalização de registros, agregação por matrícula, aplicação de regras de auditoria e exportação XLSX.

2. Organização do Código

Estruturação e padrões adotados para manutenção e legibilidade:

Estrutura em Capítulos

Os arquivos são segmentados por blocos comentados no formato padronizado:
/* === [CAPÍTULO] NOME === */ e
/* --- [Seção] Descrição --- */.

Padrão CSS e Design Tokens

Uso da metodologia BEM (Block-Element-Modifier) para classes. Definição de tokens de cores, raios e sombras em variáveis CSS no seletor :root com suporte a tema escuro via [data-theme="dark"].

Armazenamento de Estado (AppState)

A aplicação utiliza um objeto JavaScript único (AppState) para manter em memória: registros brutos lidos, servidores agrupados, resultados da auditoria, filtros ativos, competência identificada e tabela salarial em uso.

Modularização Lógica

Separação entre funções de interface (DOM/eventos), funções de ingestão de dados (parsing/pivoteamento) e motor de regras determinísticas (cálculo de Vencimento, GAJ, GAS, AQ, Teto STF e Limite de Horas Extras).

3. Uso de Dados e Privacidade

Regras e diretrizes técnicas sobre o ciclo de vida e o tratamento dos dados importados para a aplicação.

Processamento Local em Memória Volátil (RAM)

A leitura de arquivos (.xlsx, .csv, .txt) ocorre via FileReader API do navegador. Os dados são convertidos em estruturas de dados em memória JavaScript e processados localmente na máquina do usuário.

Ausência de Armazenamento Local Persistente

A aplicação não utiliza localStorage, sessionStorage, IndexedDB nem cookies para armazenar registros de folha de pagamento, dados cadastrais ou valores financeiros.

Exclusão dos Dados ao Fechar o Navegador

O encerramento da aba, fechamento do navegador ou recarregamento da página (F5) destrói o contexto de execução JavaScript. Todos os dados mantidos no AppState são liberados da memória RAM pelo gerenciador de processos do sistema operacional. Nenhum dado residual permanece gravado em disco.

Reinicialização Manual em Memória ("Mudar Folha")

A função initProcessReset redefine explicitamente todas as propriedades do AppState para valores nulos/vazios, limpando a memória antes do carregamento de um novo arquivo.

Isolamento de Rede e Ausência de Compartilhamento com IA

Nenhum dado processado é enviado para servidores externos, bancos de dados em nuvem, serviços de telemetria ou ferramentas de Inteligência Artificial. A ferramenta não realiza requisições HTTP de saída (Fetch/XHR) contendo dados de pessoal.

FAQ — Governança dos Dados

Pergunta Técnica Resposta Direta
Os dados da folha ficam salvos no navegador? Não. Os dados existem apenas enquanto a aba estiver aberta na memória RAM.
O que ocorre se a página for recarregada (F5)? Todos os dados são apagados da memória e a aplicação retorna ao estado inicial de upload.
Algum dado é transmitido para serviços de IA? Não. Não há integração, conexão ou transmissão para APIs de IA ou servidores em nuvem.
Como funciona o mascaramento de dados no modal? O identificador padrão exibido é a Matrícula. Nome e CPF são renderizados ocultos por padrão e exibidos sob demanda mediante clique no botão correspondente.
